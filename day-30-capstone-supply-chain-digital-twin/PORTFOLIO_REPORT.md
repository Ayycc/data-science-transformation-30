## Test results: how they were obtained

- **Static count, not a re-run.** Running all 30 suites inside `make run` would take far longer than the 20-minute budget and need every project's dependencies, so the report parses each `tests/test_*.py` with Python's `ast` module and counts `test*` functions (module level and in `Test*` classes). Literal `@pytest.mark.parametrize` lists are multiplied out. 2 project(s) parametrise over computed iterables, so their static case count is a lower bound; where a README states the collected count it is shown in brackets.
- **CI status** comes from a committed snapshot of the GitHub Actions API (`data/sample/ci_snapshot.json`, fetched 2026-11-13T07:04:59Z with the `gh` CLI, 33 workflow runs scanned). CI runs `make test` on Python 3.11 for each folder changed by a push, so the status shown is the last CI job for that folder. Day 30's own job runs after this commit is pushed, so it shows as pending here. Refresh with `make ci-snapshot` (needs network); the report itself builds offline.

## Lessons learned

- **Design for the network you have.** 13 of 18 projects that tried a public source could not reach any of it. The pattern used throughout was: probe, record the result in metrics.json, fall back to a seeded generator automatically, and say so in the README. Writing the public adapter anyway (Days 21, 24, 25, 26) kept the real-data path one environment variable away.
- **Synthetic data buys ground truth, and costs realism.** Known truth let projects check that estimators recover planted effects (DML ATE, MMM ROAS, promo lift here) rather than just fit well. The same author wrote the generator and the model in most projects, so headline accuracy is an upper bound; the READMEs say this, and the report keeps that caveat.
- **Say when a criterion fails.** 7 acceptance criteria were missed across 7 projects and are reported as missed, with what was tried. Several are close calls on one seed (Day 12) or within noise (Day 21), which is exactly when it is tempting to round up.
- **Pin for the CI interpreter, not the laptop.** Several projects needed environment markers because a newer wheel had no Python 3.11 build (scipy 1.18, shap 0.53, statsforecast 2.1). CI ran on 3.11 for every folder and the last job passed for 30 of 30 folders.
- **Heavy optional dependencies need a plan B.** Hugging Face and, in some builds, PyTorch's CPU index were blocked, so projects re-implemented the method (Day 25's copula and CTGAN-style GAN), used a weaker substitute (Days 11 and 21 used spaCy vectors instead of sentence-transformers), or skipped an optional comparison to stay torch-free (Day 13 GNN). Each substitution is recorded.
- **LLM features must degrade gracefully.** All three LLM projects shipped a deterministic offline path with the same interface and fake-client tests. That kept them runnable and testable, but it also means the portfolio has no measured LLM result; that gap is stated, not papered over.
- **Decision systems beat point models.** The later projects (MMM budget optimiser, bandits, this digital twin) report decisions with uncertainty (HDIs, CVaR, probability of beating baseline) and evaluate the chosen policy on fresh seeds, which avoids selecting a winner on its own noise.

## Method notes

- Tools: every requirement line is parsed (extras, environment markers, direct URLs and index options handled); names are normalised (`PyYAML` -> `pyyaml`). Different pins of the same package count once.
- Lines of code: non-blank lines that are not `#` comments in `.py` files, and not `--` comments in `.sql` files, excluding `data/`, `results/`, `docs/` and caches. Docstrings count as code.
- Key metrics, provenance, unmet criteria and caveats are curated in `src/portfolio/registry.yaml`; tests check every metric path resolves and every evidence quote appears in the README.
